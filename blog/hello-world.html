Setting Up This Site

17 August 2026 3 min read

This site is hand-written HTML and CSS with a single small JavaScript file. There is no build step, no framework, and no dependencies beyond two webfonts. Pushing to main deploys it.

That trade-off is deliberate: full control over the visual design, nothing to upgrade, and nothing that can break between me and the browser. The cost is that adding a note means copying an HTML file instead of writing Markdown.

Adding a new note

Three steps, all inside the blog/ directory:

  1. Copy _template.html to something like my-new-note.html.
  2. Fill in the title, description, canonical URL, date, and body. Every spot that needs editing is marked with an HTML comment.
  3. Add a row to the list in blog/index.html, and optionally to the Notes section on the homepage.

Then the usual:

git add .
git commit -m "note: my new note"
git push

What you can use in the body

The .prose container styles all the ordinary elements, so plain semantic HTML is enough. Headings, lists, and links all pick up the theme automatically.

Blockquotes get a magenta rule and a tinted background — useful for pulling out a definition or a result you want to emphasise.

Code

Inline code is amber. Blocks are bordered on the left in cyan and scroll horizontally when they need to: 

def gradient_step(w, grad, lr):
    return w - lr * grad

Tables

Element Styled
Headings, lists, quotes Yes

Images

Drop files in assets/img/ and reference them with ../assets/img/name.png from a note. They get a subtle border automatically.

Maths

There is no maths renderer wired up yet. If notes end up needing it, adding KaTeX is two lines in the <head> — a deliberate choice not to load it on every page until it earns its place.
